## 読み取る情報

systemd を使う Linux では、自分のユーザーセッションのログ、つまり自分のサービスと自分のプログラムのクラッシュレポートを読み取ります。Omarchy では Hyprland とバーも確認します。システム全体のログを読むことはなく、追加のアクセス権を求めることもありません。

サービスが停止したこと、どのように終了したか、どのプログラムがクラッシュしたかを読み取ります。ログの行に書かれた内容は読み取りません。そのため、ログのテキストが保存されたり、コンピューターの外に送られたりすることはありません。

## 問題として扱うもの

何度も再起動するサービス、1日に何度も失敗したサービスや停止したままのサービス、メモリ不足になったサービス、クラッシュしたプログラムです。Omarchy では、Hyprland やバーのクラッシュ、Hyprland の設定エラーも対象です。

1回だけの再起動や実行失敗はよくあることなので、通知しません。数回失敗しても、その後は正常に動いているサービスも同様です。

テストやエージェントが操作するブラウザー（headless、Playwright、Puppeteer、CI）は通知しません。サービスの停止中や再起動中に終了したプログラムも通知しません。開発中の実行も対象外です。コーディングエージェントが実行したもの、テスト、一時フォルダーやキャッシュフォルダーから実行したプログラムが含まれます。何度もクラッシュするプログラムについては、発生回数と時期を記載したToDoを1件作成します。

スクリプトは python3 や node ではなく、backup.py のようにスクリプト自体の名前で表示します。

## 届く内容

何が起きたのか、なぜ問題なのか、何ができるのかを平易な言葉で説明するToDoが届きます。原因を示すコマンドは「もっと見る」の下に表示されます。チャットで尋ねると、The Machine が詳しく調べます。変更を伴う操作は、実行と同じく、承認を待ってから行われます。

安全に対処できる場合は、ToDoに実行ボタンが表示されます。停止したままの自分のサービスは再起動し、Omarchy ではバーを復旧します。実行すると、そのコマンドだけが実行され、結果はToDoのチャットに表示されます。The Machine 自身のサービスや OpenClaw Gateway に変更を加えることはありません。

同じ問題について作成されるToDoは2週間に1件までで、対応するToDoが未完了の間は作成されません。新しいToDoは1日に最大2件です。

## ターミナルで確認する

`assistant doctor` を実行すると、過去1日分の同じ問題が一覧表示されます。

## その他のコンピューター

macOS、Windows、systemd を使わないコンピューターでは何も読み取らず、そのことを `assistant doctor` で知らせます。

ホスト型の Machine は、サーバーを稼働させ続けるのがこちらの役割です。問題はToDoとしてではなく、The Machine チームに通知されます。

## オフにする

config.json で `"computer_logs": false` を設定し、サービスを再起動します。
