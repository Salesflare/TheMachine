## 创建例行程序

打开侧边栏中的**例行程序**，用一句话说明要做什么、什么时候做，例如：“每周一早上 9 点，汇总未成交的商机”或“每个工作日早上，列出我还没回复的邮件”。然后点击**添加**。

如果没有指定时间，任务会在 8:00 运行。时间以你的 Machine 时钟为准。首次运行后，The Machine 会为它起一个简短的名称。

点击**添加**后会先试运行，让你看看结果，再决定是否保留。试运行不会发送或保存任何内容。之后，点击**添加**会让它按设定的频率运行；点击**更改**可以尝试不同的描述或新名称；点击**取消**则会将其移除。

## 模板

在例行程序页面底部的**模板**中，点击**添加**即可启用现成的例行程序。它会立即运行一次，之后每天早上 7:30 运行（清理垃圾邮件每小时运行一次，订阅和试用期每月运行一次）。模板卡片会像其他例行程序一样显示其描述，点击**编辑**可以修改描述或名称。

如果收到很多邮件简报，而邮件简报清理尚未开启（每周收到 25 封或更多，且至少来自 5 位发件人），待办事项上方会显示收到的邮件数量和清理方式，并提供**开启**和**不了，谢谢**选项。

如果一周内有 5 封或更多邮件被手动移入垃圾邮件文件夹，也会以同样的方式推荐清理垃圾邮件。点击**开启**会像在此处点击**添加**一样启用它。点击**不了，谢谢**后不会再收到此推荐。如果你以前用过该模板，也不会再次推荐。

**邮件简报清理**会按类别（工作和个人）分别创建待办事项，列出过去一天收到的邮件简报。每封邮件都可以选择**保留**或**退订**。退订时会使用邮件列表提供的一键退订链接；如果已开启邮件发送功能，也可以从你的地址发送退订邮件。否则，The Machine 会在自己的浏览器中打开邮件列表页面并进行退订。如果页面需要登录、验证码或选择操作，需要你来完成：对应的邮件行会说明原因，并提供**打开取消订阅页面**。

收据、订单和付款通知不会列入其中。通过群组地址（例如 Google 群组）收到的邮件会列在发件人名下，也不会帮你退订该群组。如果发件人没有提供退订方式，对应的邮件行会显示**手动退订**。

**清理垃圾邮件**会按类别创建待办事项，列出看起来像垃圾邮件的陌生发件人邮件，每封都可以选择**垃圾邮件**或**不是垃圾邮件**。Outlook 会将垃圾邮件移到“垃圾邮件”文件夹，Gmail 会将其标记为垃圾邮件。它每小时检查一次，因此垃圾邮件通常会在你打开待办事项前就列出来。待办事项仍处于打开状态时，新发现的垃圾邮件也会添加到其中。

如果 Gmail 以只读方式连接（例如在托管的 Machine 上），就无法将邮件移入垃圾邮件文件夹。这种情况下，点击**垃圾邮件**会显示一个链接，让你在 Gmail 中标记邮件；The Machine 也会记住该发件人属于垃圾邮件。如果没有连接邮件账户，模板会显示**连接邮箱**，而不是**添加**。

陌生发件人是指你从未给对方写过邮件的人。邮件主题中的“Re:”只有在你参与过该邮件会话时才算回复。如果你曾在待办事项中或邮箱里将某个发件人的邮件标记为垃圾邮件，但之后又收到该发件人的邮件，这封邮件会出现在下一个待办事项中，并标记为**之前已标记为垃圾邮件**。你手动移入垃圾邮件文件夹的邮件也会帮助 The Machine 识别类似邮件。

在待办事项中确认之前，不会进行任何更改。点击发件人可以先阅读邮件：邮件仍会保持未读状态，也不会有任何更改。从清理垃圾邮件待办事项中打开邮件时，邮件中的网络图片不会加载，因此发件人不会知道你打开过邮件。你已经做出决定的发件人不会再次出现。没有收到邮件简报或垃圾邮件的日子不会创建待办事项，这些待办事项也不会发送通知。

决定好所有发件人的处理方式后，待办事项会显示已完成，并出现**标记为已完成**按钮。

**每日摘要**每天会将值得你花时间阅读的少量邮件简报整理成一个待办事项。每封邮件都会用一句话说明它与你相关的原因。点击邮件即可阅读，也可以点击**在邮件中打开**。摘要只包含邮件简报，不会包含个人邮件、收据、你已退订的发件人邮件，也不会包含你已经读过的邮件。如果没有特别值得关注的内容，就不会创建待办事项。

The Machine 会根据你打开、加星标或归档未读邮件的行为，以及你对每条推荐点击**多来点这样的**或**减少类似内容**来了解你关心的内容。它选择的主题会显示在例行程序卡片的**更多**和**减少**下。点击 × 可以移除主题，也可以添加自己的主题。虚线框主题是 The Machine 自行学到的。新摘要会替换尚未完成的摘要，也不会发送通知。

The Machine 只会读取每封新邮件简报的发件人、主题和开头，并就这些内容向你的 AI 提出一个简短问题。每天的问题数量有限，以控制成本。点击**更改时间**可以调整运行时间。修改描述后，它就会像其他例行程序一样按照你的描述运行。

**生日**会为今天生日的亲密联系人分别创建待办事项：也就是你会亲自联系的人，例如朋友、家人和经常联系的人。每个待办事项都会附上一条简短的祝福草稿，放在你通常与对方联系的地方，例如对方的 WhatsApp 聊天或邮件往来中，并使用对方的语言。只有你发送后，祝福才会发出。没有人过生日的日子不会创建待办事项。

生日信息来自你的日历（Google 的生日活动和“生日”日历每天早上读取，即使日历尚未同步也会读取；以及 Outlook 的“生日”日历）、自托管 Machine 上的 Google 联系人，以及 Graph 中个人资料的 Birthday 日期字段。如果这些来源都没有生日信息，结果会显示**暂无生日信息**，并说明如何添加。

**从Facebook导入生日**：开启生日后，系统会创建一个待办事项，邀请你读取 Facebook 的生日页面。点击**导入**后，The Machine 会在自己的浏览器中打开该页面，滚动页面，直到加载出每个月的内容，并读取每位好友的姓名和生日。页面会显示找到的生日数量，以及通过姓名和姓氏匹配到 Graph 中联系人的名单。如果有多个联系人同名，该姓名会被跳过并列出。

只有点击**保存**才会保留这些信息，并写入每位联系人的个人资料页面，包括生日，以及尚无头像的联系人的 Facebook 头像。你在此处设置的生日或头像会保留；已有头像不会被替换。任何信息都不会写入 Facebook。

The Machine 不会自动再次读取生日页面；点击待办事项中的**重新导入**才会再次读取。浏览器必须已登录 Facebook。如果还没有登录，请点击待办事项中的**登录 Facebook**并在浏览器中登录；登录后，The Machine 会自动读取页面。The Machine 不会替你登录。

Graph 中没有对应联系人的好友会单独计数，并显示部分姓名。点击**将……添加为个人联系人**可以一次性添加所有这些好友，也可以在点击**保存**后添加：每位联系人只会添加姓名和生日，不会与工作 Fleet 共享。如果 Graph 中已有同名联系人，或你以前永久删除过同名联系人，该好友会被跳过。只有你会主动联系的人才会收到生日提醒。

点击待办事项中的**撤销**可以移除刚添加的联系人，即使你已经点击过**重新导入**也可以撤销。

**订阅和试用期**每月会读取收据、发票和续订通知，并将订阅整理到一个待办事项中，列出每项订阅的费用、下次扣款时间，以及试用期即将结束或价格上涨的提示。只会列出 The Machine 确认无误的订阅。没有找到订阅时，不会创建待办事项。

为每项订阅选择**保留**或**取消**。保留的订阅之后不会再次询问，除非价格发生变化。点击**取消**会提供取消页面，或一封请求对方取消订阅的草稿。只有你发送后，草稿才会发出。两次运行之间，The Machine 会每天检查一次；如果试用期结束或续订扣款将在 7 天内发生，就会创建待办事项。

模板例行程序会保留模板原有的描述，并使用自己的代码运行，不会消耗你的 AI 方案额度（清理垃圾邮件会先用代码列出陌生发件人的新邮件，只有找到邮件时才会向你的 AI 提出一个简短问题）。更改名称不会影响这一点。修改描述后，它就会像其他例行程序一样按照你的描述运行。

邮件简报清理和清理垃圾邮件仍会创建同样的待办事项，为每封邮件提供选项。编辑生日模板后，结果会直接显示，最多附带一条草稿，而不会为每个人分别创建待办事项。在**编辑**中点击**恢复为模板**可以还原模板的描述。

## 例行程序的工作方式

到设定的时间后，你的 Machine 会读取所需信息，例如消息、会议和 Graph，然后将结果显示在例行程序页面上。每次运行都会显示**已备好**、**暂无新内容**（并说明原因）或**没起作用**（并说明原因）。运行结束时没有结果，也算作运行失败，不算完成。

例行程序只会读取信息：你的消息、网页、GitHub，以及浏览器中的 X 等网站。它们不会发送、回复、发布内容或更改任何内容。只有模板会更改邮件，而且只会执行你在待办事项中确认的操作。

如果例行程序的任务最后一步是发布内容或发送消息，它会完成之前的所有步骤，并显示草稿，例如**将在 X 上发布：**。实际运行后，草稿会作为待办事项显示，供你批准；试运行只会显示草稿。例行程序名称会说明内容和发布位置，按钮会标明操作，例如**发布**；点击下方的**来自你的例行程序**可以打开对应的例行程序。

待办事项会归入要发布内容的账户所属类别，例如公司 X 账户的“工作”类别，因此不会要求你移动待办事项。

运行时可以根据任务内容调用已启用的[技能](skills.md)：只有相关技能才会被完整读取。结果会在**已使用：**下列出这些技能。技能不会让例行程序发送或更改任何内容。

你的例行程序会显示在**你的例行程序**下方，位于所有建议之后。较长的结果会折叠成简短预览；点击**展开**或直接点击预览即可查看完整内容。

每次运行都会参考上一次的结果，因此可以说明自上次运行后发生了哪些变化。

成功运行后，你的 Machine 可能会自行编写一份读取步骤配方，记录每次都相同的读取操作，例如要查看哪些邮件或 GitHub 更改。之后运行时会先用纯代码执行这些读取操作，再由 AI 判断哪些内容重要并生成结果，从而减少 token 用量。配方只会读取信息；如果配方失效，运行时会自动读取并修复。点击 ⋯ 菜单中的**高级：脚本步骤**可以查看配方。

## 错过的运行

如果你的 Machine 关机或正忙，错过的运行不会累积：只会补上最近一次运行。每个日期最多运行一次，即使重启也一样。

例行程序会逐个运行。如果 AI 方案的用量不足，它们会像所有后台任务一样等待。点击**立即运行**可以马上运行；准备好后，结果会显示在卡片上。

## 修改或停止例行程序

相关选项位于例行程序的 ⋯ 菜单中。点击**编辑**可以更改名称和任务内容；运行时间和已有结果不会改变。点击**更改时间**可以用自己的话设定新的频率，例如“每个工作日早上 8 点”。这两个页面都有**保存**和**取消**按钮；在电脑上也可以按 Esc 键或点击页面外部取消。

在**编辑**页面中，点击**试用**可以用新的描述运行一次，并在页面中查看结果。点击**保存**前，例行程序仍会保持原样。

点击**暂停**可以停止运行，直到点击**恢复**为止。已暂停的例行程序会显示在页面底部的**已暂停**下方，暂停期间错过的运行不会在恢复后补上。点击**停止**可以永久结束例行程序。

如果你在例行程序的待办事项中点击**要求修改**，或在聊天中留言，而且你的要求适用于之后的每次运行，例如“永远不要用表情符号”，待办事项和聊天回复下方都会提供**同时更改例行程序**。页面会显示例行程序描述将如何更改；只有点击**更改**后，例行程序才会更新。点击**保持原样**则不作更改。只针对当前草稿的修改不会提供此选项。

## 高级：脚本步骤

不需要脚本：用自己的话说明例行程序要做什么，你的 Machine 会处理其余部分。

高级用户还可以让例行程序在自己的 Machine 上运行自定义命令：打开 ⋯ 菜单，选择**高级：脚本步骤**。只有例行程序已有脚本步骤时，点击**编辑**才会显示这些步骤。点击**获取数据**会先运行命令，在指定文件夹中执行（未指定时使用主文件夹），运行时间不超过设定的秒数。命令输出会传给本次运行进行处理。如果没有文字描述，命令输出就会作为结果。

运行后，**检查**会将结果作为输入。如果命令以错误状态退出，运行结果会显示**没起作用**以及检查步骤给出的信息。获取数据命令运行失败时也会显示相同的信息。

每条命令必须写在一行中，并且不通过 shell 运行：不能使用管道或变量。脚本步骤由你设置，只会保存在你的控制面板中。试运行和点击**试用**时也会运行获取数据步骤，并会说明这一点；但仍不会发送或保存任何内容。例行程序不会发送内容，因此脚本步骤只能用于读取信息。

## 从 OpenClaw 任务导入

如果你以前在 OpenClaw 中创建过定时任务，你的 Machine 会读取这些任务（不会修改任务），并将适合的任务作为例行程序显示在**建议的**下方。每个任务都已运行过一次，因此你可以看到实际结果。

The Machine 会保留你对任务的修改，并移除任务发送或发布的内容。如果任务运行过脚本，或读取过脚本任务收集的信息，这些内容会作为获取数据步骤一并添加。点击**添加**会将任务设为例行程序；点击**不了，谢谢**后就不会再询问你是否添加该任务。提醒你完成某件事的任务会在待办事项页面显示为重复待办事项建议。

添加建议前，你可以通过其 ⋯ 菜单中的**编辑**和**更改时间**像修改其他例行程序一样修改它。点击**再次运行**会按当前描述立即运行，例如在安静的周末后查看更新。它只会读取信息，每次点击只运行一次，新结果会替换旧结果。

同时最多会有三个待处理建议。例行程序成功运行一周后，会询问你**要关闭旧的OpenClaw任务吗？**。只有点击**关闭**才会关闭旧任务；你可以在 OpenClaw 中重新开启。

## 根据你的日常操作提供建议

即使没有使用 OpenClaw，你的 Machine 也会发现你经常重复的工作，并在**建议的**下方将其推荐为例行程序。它会寻找以下情况：

- 连续三次或更多次提出相同的要求，例如每周一说“汇总未解决的支持工单”；
- 定期发送的邮件，例如每周发给团队的报告；
- 每周持续收到的邮件简报和更新邮件；
- 其他人每周都会在其中发消息的繁忙 Slack 频道；
- 你逐封转发给同一个人的邮件，例如转发给伴侣的学校和社团邮件：为对方创建每周摘要，可以省去逐封转发；
- 你定期回复的相同请求，例如每月批准同一个人的申请。

每条建议都会说明 The Machine 发现了什么，例如“连续提出了 4 次”或“三周内转发了 6 封邮件给 Sam”，并且已经运行过一次，因此你可以看到实际结果。你可以考虑创建团队周报、每周会议简报、支持或开发摘要、数据动态，或你收到的邮件简报摘要。

The Machine 只会推荐与你相关且明确有用的内容：新闻摘要只会根据你订阅的邮件简报生成，不会提供泛泛的新闻摘要。没有合适内容时，就不会提供建议。

The Machine 每天最多检查一次，每周最多新增一条建议，也不会发送通知。点击**不了，谢谢**后，那条建议不会再次出现。转发和回复会保留在发送邮件的账户中，因此工作和个人邮件不会混在一起。所有内容都会保留在你的 Machine 上。你定期完成的待办事项会以重复待办事项建议的形式显示。

## 例行程序和重复待办事项

重复待办事项（recurring.md）会提醒你完成某件事。例行程序则由你的 Machine 自动处理任务并向你显示结果。“每月 1 日付房租”适合设为重复待办事项；“每周五告诉我哪些商机进展停滞”适合设为例行程序。
