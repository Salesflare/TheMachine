## 保留哪些内容

The Machine 会导入约一年的旧邮件、会议记录，以及 WhatsApp、Slack 和 Teams 消息。你可以搜索这些内容，也可以按含义搜索；在线程中也能看到这些内容，[日历](calendar.md)中则会显示过去的会议。

**连接**中的每个连接都会说明内容的追溯范围，例如 **历史记录：追溯至** 2025 年 11 月。

## 对你的 Graph 有什么帮助

你的 [Graph](graph.md) 会将这些内容纳入计算：你和他人的关系有多密切、上次交谈的时间、谁认识谁，以及联系人和组织本身。个人或组织的时间线也会显示这些内容，因此始终能看到最近一次联系。你的 Fleet 在使用工作账户回答“谁认识某人”时也会用到这些内容，并遵循与新邮件相同的[共享规则](sharing-rules.md)。

## 绝不会做什么

这些内容绝不会生成待办或承诺，不会被视为新内容，不会启动检查，也不会添加到项目中。个人历史记录会像个人邮件一样保持私密。除了按含义搜索外，没有 AI 模型会读取这些内容。

## 何时运行

首次查看消息后，历史记录导入便会开始。每个连接都要等首周结束后才会开始导入，之后添加的连接也一样。导入会在后台缓慢进行；检查或同步运行时、服务要求降低速度时，或 The Machine 空间不足时，导入会暂停。新消息始终优先处理。

邮箱历史记录导入完成后，The Machine 会再读取一次保留的邮件，以提取预订和票务详情，因此较早的预订也会显示在[行程和活动](notes.md)中。读取速度同样缓慢，暂停原因也相同。

导入会使用各连接已有的访问权限，无需再批准任何内容。

## 追溯范围

约一年。在你自己的电脑上，可以在设置文件中通过 `history_days` 更改追溯范围（设为 0 即可关闭，最多为 730）。Telegram 和其他来源不会导入较早的历史记录。

LinkedIn 和 X 消息最多追溯 90 天，读取速度非常慢：每小时只进行少量小批量读取，只在白天读取；如果网站限制访问，则会暂停一天，以确保账户安全（`social_history_days`，设为 0 即可关闭）。
