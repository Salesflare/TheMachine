## 显示内容

打开 **设置**，然后点 **动态**。列表中的每一行代表 The Machine 完成的一件事，按日期倒序排列：

- 完成了什么，以及结果：已发送、已拒绝、失败或已撤销
- 完成时间、使用的账号或应用，以及[执行依据](activity.md#what-allowed-it)
- 如果有对应待办，会显示待办链接
- 对于你连接的 AI，例如 ChatGPT 或 Claude：名称后会标注 **（已连接的 AI）**，方便你和 The Machine 本身区分

列表会显示消息和回复、文档和日历更改、网页操作、已合并的修复、编程代理、Fleet 问答、发送给 The Machine 团队的心得、技能、Graph 导入、你让聊天忘记的事实（可点 **撤销**）、添加或移除的连接，以及团队根据[支持访问权限](get-support.md#support-access)进行的每次查看，包括被拒绝的查看。

## 执行依据

每条消息、文档或日历更改、网页操作和已合并的修复，都会记录当时的执行依据：

- **已在待办中批准** 或 **已在 Telegram 中批准**：你点了对应的**发送**、**确认**或**合并**按钮
- **已通过语音批准**：你在 Talk 中说了“同意”
- **已点击“执行”**：你点了待办中的**执行**
- **已在聊天中询问**：你用文字提出了请求，并显示消息的开头。只有当这些文字仍在你自己的消息中时，才会显示引用内容。
- **自动发送的跟进**、**小修复，已自动合并**、**自动创建的私人文档**或**自动提前准备**：依据你设置的选项或 The Machine 自己的规则
- **未记录批准**：没有记录到任何批准信息。这类情况也会发送到我们的[错误报告](error-reports.md)，以便我们找到遗漏的环节。

网页操作还会显示待办在网页上点击或输入的执行记录，以及这次执行的依据。稍后处理后仍在继续的工作，会保留推迟前的执行依据。

对于开始记录之前的旧条目，会保留原来的说法，例如 **等你确认后**。

## 筛选动态

在列表顶部选择类别，例如 **消息**或 **Fleet**。选择 **已拒绝或已拦截**，只查看未能完成的事项及其原因。点 **展开**可加载更早的动态。

## 其他位置

待办的聊天记录仍会显示完整过程，动态中也会提供链接。Fleet 中的 **动态**会显示你的 Fleet 和心得的相同记录，心得旁还会有 **撤回**。在设置中，打开 **安全**，然后点 **在活动中查看每次浏览**，即可查看团队的每次查看记录。

动态只显示发生过的事，不会改变 The Machine 可以执行的操作。
