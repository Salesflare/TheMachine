## 읽어 오는 항목

받은 편지함과 보낸 편지함의 최근 7일 치 메일을 연결할 때 가져오고, 이후에는 새 메일을 모두 가져와요. 보낸 메일도 포함되므로 어떻게 글을 쓰고 어떤 약속을 했는지 학습해요. 다른 폴더는 읽지 않아요.

메일함의 내용은 바뀌지 않아요. 다만 The Machine이 보낸 메일은 보낸 편지함에 사본이 저장돼요. 메일을 읽음으로 표시하지 않아요.

## 할 수 있는 작업

보내기 버튼을 눌렀을 때만 같은 비밀번호를 사용해 제공업체의 메일 서버(SMTP)로 이메일을 보내요. 보낸 편지함에 사본이 저장돼요. 답장은 기존 메일 스레드에 이어지고, 서명은 설정에 지정된 서명을 사용해요. 지정된 서명이 없으면 보낸 메일 끝에 있는 서명을 사용해요.

## 연결하기

1. 대시보드에서 **연결**을 열고 **이메일**을 선택한 다음 **기타 이메일**을 선택해요.
2. 이메일 주소와 비밀번호를 입력해요.
3. **연결**을 눌러요.

많은 제공업체에서는 메일 앱에 일반 비밀번호 대신 앱 비밀번호를 사용해야 해요. 제공업체 계정 설정에서 앱 비밀번호를 만들어 주세요.

- iCloud: account.apple.com에서 앱 전용 비밀번호를 만들어요.
- Yahoo: 계정 보안에서 앱 비밀번호 생성을 선택해요.
- Fastmail: 설정, 개인정보 보호 및 보안, 앱 비밀번호로 이동해요.
- Telenet: 일반 Telenet 메일 비밀번호를 사용해요.
- Zoho Mail에서 2단계 인증을 사용하는 경우: Zoho 계정의 보안 설정에서 애플리케이션 전용 비밀번호를 만들어요.
- Proton Mail: 같은 컴퓨터에서 Proton Mail Bridge를 실행하고 Bridge에 표시되는 비밀번호를 사용해요. 같은 컴퓨터에서 실행되는 The Machine에서만 사용할 수 있어요. The Machine은 Bridge 인증서의 지문을 표시하고 해당 인증서만 신뢰해요.

대부분의 제공업체는 서버 설정이 자동으로 입력돼요. 제공업체를 찾을 수 없나요? **서버 설정**을 열고 메일 앱에 필요한 제공업체 설정을 입력해요. IMAP 및 SMTP 서버, 포트, 보안 방식(SSL/TLS 또는 STARTTLS)을 입력하면 돼요. The Machine은 TLS 연결이 아니면 접속하지 않아요.

자체 도메인에서도 Gmail 또는 Microsoft 메일을 사용하나요? 대신 **Gmail** 또는 **Outlook**을 선택해요. 비밀번호 없이 로그인해요. 서버 설정에 입력한 서버도 해당 연결에 적용돼요. Microsoft는 더 이상 메일 앱에서 비밀번호를 받지 않아요.

## 연결이 중단되는 경우

- **메일 서버에서 비밀번호를 거부했어요**: 비밀번호를 변경했거나 앱 비밀번호가 삭제됐어요. 새 비밀번호로 다시 연결해요.
- **메일 서버에서 발신용 비밀번호를 거부했어요**: 메일이 전송되지 않았어요. 다시 연결해요. 계속 거부되면 서버 설정에서 SMTP 서버를 확인해요. 그동안에는 메일을 읽기만 해요.
- **메일 서버에 연결할 수 없어요**: 자동으로 다시 시도해요. 계속 실패하면 서버 설정에서 서버 이름을 확인해요.
- **메일 서버 인증서의 이름이 다른 경우**: 공유 호스팅에서는 자체 서버 이름으로 응답하는 경우가 많아요. 서버 설정에 표시된 이름을 입력해요. The Machine은 인증서 확인을 건너뛰지 않아요.

## 연결 해제하기

**연결**에서 계정을 열고 **세부 정보**, **연결 해제**를 차례로 선택해요. 메일을 읽지 않게 되며 이미 가져온 메일은 그대로 남아요. 제공업체에서도 앱 비밀번호를 삭제해 주세요.
