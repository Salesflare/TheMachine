## 루틴 만들기

사이드바에서 **루틴**을 열고, 한 줄로 할 일과 실행 시점을 적어 주세요. 예를 들면 "매주 월요일 9시에 진행 중인 거래 요약하기" 또는 "평일 아침마다 아직 답장하지 않은 이메일 목록 보여 주기"처럼요. 그런 다음 **추가**를 누르세요.

시간을 지정하지 않으면 8:00에 실행돼요. 시간은 The Machine의 시계를 기준으로 해요. 처음 실행하면 짧은 이름이 붙어요.

**추가**를 누르면 먼저 테스트 실행을 해요. 결과를 확인한 뒤 저장할 수 있어요. 아무것도 전송하거나 저장하지 않아요. 그다음 **추가**를 누르면 설정한 주기로 실행되고, **변경**을 누르면 다른 문구나 새 이름으로 시도해요. **취소**를 누르면 취소돼요.

## 템플릿

루틴 맨 아래에 있는 **템플릿**에서 **추가**를 누르면 미리 만든 루틴이 켜져요. 바로 한 번 실행된 뒤 매일 아침 7:30에 실행돼요. 스팸 정리는 매시간 실행돼요. 카드를 열면 다른 루틴처럼 문구를 확인할 수 있고, **수정**을 누르면 문구나 이름을 바꿀 수 있어요.

뉴스레터가 많이 도착하는데 뉴스레터 정리가 꺼져 있으면, 할 일 위에 도착한 뉴스레터 수와 처리 방법을 알려주는 문구가 표시돼요. 일주일에 25개 이상, 발신자가 5명 이상일 때 표시되며, **켜기**와 **아니요, 괜찮아요**를 선택할 수 있어요.

일주일 동안 이메일을 5개 이상 직접 스팸으로 이동한 경우에도 같은 방식으로 스팸 정리를 제안해요. **켜기**를 누르면 여기서 **추가**를 누른 것처럼 루틴이 추가돼요. **아니요, 괜찮아요**를 누르면 다시 제안하지 않아요. 이전에 사용한 템플릿은 다시 제안하지 않아요.

**뉴스레터 정리**는 업무용과 개인용 영역별로 할 일을 하나씩 만들고, 지난 하루 동안 받은 뉴스레터를 표시해요. 각 항목에서 **유지** 또는 **구독 취소**를 선택할 수 있어요. 구독 취소는 목록에 있는 원클릭 링크를 사용하거나, 이메일 전송이 켜져 있으면 내 주소에서 구독 취소 이메일을 보내요. 둘 다 사용할 수 없으면 The Machine이 자체 브라우저에서 목록의 구독 취소 페이지를 이용해요. 로그인이나 보안 문자 입력, 페이지에서 선택해야 하는 항목은 직접 처리해야 해요. 해당 항목에는 이유와 함께 **수신 거부 페이지 열기**가 표시돼요.

영수증, 주문 내역, 결제 알림은 제외돼요. Google Group처럼 그룹 주소를 통해 받은 이메일은 작성자 이름 아래 표시되고, 그룹 구독을 취소하지 않아요. 발신자가 자체 구독 취소 방법을 제공하지 않으면 해당 항목에 **직접 구독 취소**가 표시돼요.

**스팸 정리**는 영역별로 할 일을 하나씩 만들어요. 스팸처럼 보이는 알 수 없는 발신자의 이메일을 표시하고, 각 항목에서 **스팸** 또는 **스팸 아님**을 선택할 수 있어요. Outlook에서는 스팸을 정크 메일로 이동하고, Gmail에서는 스팸으로 표시해요. 매시간 확인하므로 보통 스팸이 도착하기 전에 처리할 수 있어요. 할 일이 열려 있는 동안 새 스팸이 오면 같은 할 일에 추가돼요.

호스팅된 Machine처럼 Gmail을 읽기 전용으로 연결한 경우에는 이메일을 스팸으로 이동할 수 없어요. 이때 **스팸**을 누르면 Gmail에서 직접 스팸으로 표시할 수 있는 링크가 제공되고, The Machine은 해당 발신자를 스팸으로 기억해요. 메일 계정이 연결되지 않았으면 템플릿에서 **추가** 대신 **메일 연결**이 표시돼요.

알 수 없는 발신자란 이전에 이메일을 주고받은 적이 없는 발신자를 말해요. "Re:"가 붙어 있어도 내가 참여한 대화 스레드에서만 같은 대화로 취급해요. 할 일이나 메일함에서 스팸으로 표시한 발신자의 이메일이 다시 도착하면 다음 할 일에 **이전에 스팸으로 표시했어요**라고 표시돼요. 직접 스팸으로 이동한 이메일도 비슷한 이메일을 찾는 데 활용돼요.

할 일에서 확인하기 전까지는 아무것도 바뀌지 않아요. 발신자를 눌러 이메일을 먼저 읽어도 읽지 않은 상태로 유지되며, 아무것도 바뀌지 않아요. 스팸 정리에서는 웹에 있는 이미지가 로드되지 않으므로 발신자는 이메일을 열어 봤는지 알 수 없어요. 한 번 결정한 발신자에 대해서는 다시 묻지 않아요. 뉴스레터나 스팸이 없는 날에는 할 일이 만들어지지 않으며, 이런 할 일은 알림을 보내지 않아요.

모든 발신자에 대해 결정을 내리면 할 일이 완료됐다고 표시되고, **완료** 버튼이 나타나요.

**일일 요약**은 매일 한 번, 시간을 들여 읽을 만한 뉴스레터 몇 개를 하나의 할 일로 골라 줘요. 각 항목에는 왜 중요한지 한 줄로 설명돼요. 항목을 눌러 이메일을 읽거나 **메일에서 열기**를 선택하세요. 뉴스레터만 포함돼요. 사람에게서 온 이메일, 영수증, 구독을 취소한 발신자의 이메일은 포함되지 않으며, 이미 읽은 이메일도 제외돼요. 눈에 띄는 내용이 없으면 할 일이 만들어지지 않아요.

열어 보거나 별표 표시하거나 읽지 않은 상태로 보관한 항목, 그리고 각 추천 항목의 **이런 항목 더 보기**와 **이런 항목 줄이기**를 바탕으로 관심사를 파악해요. 고르는 주제는 루틴 카드의 **더 많은**과 **줄이기** 아래에 표시돼요. ×를 눌러 항목을 삭제하거나 직접 추가할 수 있어요. 점선으로 표시된 항목은 The Machine이 스스로 파악한 주제예요. 새 요약이 기존 요약을 대체하며, 알림은 보내지 않아요.

새 뉴스레터마다 발신자, 제목, 앞부분만 읽고 AI에 짧은 질문 하나를 해요. 비용을 낮게 유지할 수 있도록 하루 사용량에 제한을 둬요. **시점 변경**에서 실행 시간을 설정할 수 있어요. 문구를 한 번 바꾸면 이후에는 직접 작성한 문구대로 다른 루틴처럼 실행돼요.

**생일**은 오늘 생일인 가까운 연락처마다 할 일을 만들어요. 친구, 가족, 자주 연락하는 사람처럼 직접 연락하는 사람을 대상으로 해요. 평소에 대화하는 곳에서 짧은 축하 문구 초안을 작성해 줘요. 상대방의 WhatsApp 채팅이나 이메일 대화처럼 자주 사용하는 곳에서, 상대방의 언어로 작성돼요. 직접 보내야만 전송돼요. 생일이 없는 날에는 할 일이 만들어지지 않아요.

생일 정보는 캘린더, 직접 호스팅하는 Machine의 Google 연락처, Graph에 있는 사람의 Birthday 날짜 필드에서 가져와요. 캘린더에서는 Google의 생일 일정과 생일 캘린더를 매일 아침 확인해요. 동기화되지 않은 경우에도 확인하고, Outlook의 생일 캘린더도 확인해요. 아직 생일 정보가 하나도 없으면 결과에 **생일 정보가 아직 없어요**와 추가 방법이 표시돼요.

**Facebook에서 생일 가져오기**: 생일을 켜면 Facebook 생일 페이지를 읽을 수 있는 할 일이 만들어져요. **가져오기**를 누르면 The Machine이 자체 브라우저에서 Facebook을 열고, 모든 달의 내용이 로드될 때까지 스크롤한 다음 친구의 이름과 생일을 읽어요. 찾아낸 사람 수와 이름 및 성으로 Graph의 사람과 일치한 친구를 보여 줘요. 같은 이름을 가진 사람이 여러 명이면 건너뛰고 목록에 표시해요.

각 사람의 페이지에서 **저장**을 눌러야 정보가 저장돼요. 생일과, 아직 사진이 없는 사람의 Facebook 프로필 사진이 저장돼요. 직접 설정한 생일이나 사진은 그대로 유지되고, 이미 사진이 있는 사람의 사진은 바뀌지 않아요. Facebook에는 아무것도 기록하지 않아요.

자동으로 다시 읽지 않아요. 할 일에서 **다시 가져오기**를 눌러야 해요. 브라우저에서 Facebook에 로그인되어 있어야 해요. 로그인되어 있지 않으면 할 일에서 **Facebook에 로그인**을 누르고 로그인하세요. 로그인하면 페이지를 자동으로 읽어요. The Machine이 대신 로그인하지는 않아요.

Graph에 없는 친구도 몇 명인지와 이름 몇 개를 함께 표시해요. **…을 개인 연락처로 추가**를 누르면 저장한 뒤에도 한꺼번에 추가할 수 있어요. 각 연락처에는 이름과 생일이 포함되며, 업무용 Fleet과는 공유되지 않아요. Graph에 이미 같은 이름을 가진 사람이 있거나 이전에 영구 삭제한 사람이 있으면 건너뛰어요. 생일 알림은 여전히 직접 연락하는 사람에게만 제공돼요.

할 일에서 **실행 취소**를 누르면 해당 사람들만 정확히 삭제돼요. **다시 가져오기**를 한 뒤에도 마찬가지예요.

템플릿의 루틴 문구를 그대로 두면 내 AI 요금제를 사용하지 않고 자체 코드로 실행돼요. 스팸 정리는 먼저 코드로 알 수 없는 발신자의 새 이메일만 나열하고, 해당 이메일이 있을 때만 AI에 짧은 질문 하나를 해요. 새 이름을 붙여도 이 방식은 유지돼요. 문구를 한 번 바꾸면 이후에는 직접 작성한 문구대로 다른 루틴처럼 실행돼요.

뉴스레터 정리와 스팸 정리는 계속 이메일마다 선택할 수 있는 같은 할 일로 표시돼요. 생일 문구를 수정하면 결과와 최대 하나의 초안이 제공되고, 사람마다 할 일이 만들어지지는 않아요. **수정**에서 **템플릿으로 돌아가기**를 누르면 원래 문구로 돌아가요.

## 루틴의 동작 방식

설정한 시간이 되면 The Machine이 메시지, 회의, Graph 등 필요한 정보를 읽고 결과를 루틴 페이지에 표시해요. 각 결과에는 **준비 완료**, **새로운 항목이 없어요**(이유 포함), **작동하지 않았어요**(이유 포함) 중 하나가 표시돼요. 결과가 나오지 않고 실행이 끝난 경우에는 완료가 아니라 작동 실패로 처리돼요.

루틴은 읽기만 해요. 메시지, 웹페이지, GitHub, 브라우저에서 여는 X 같은 사이트를 읽어요. 전송하거나 답장하거나 게시하거나 내용을 변경하지 않아요. 메일을 변경하는 건 템플릿뿐이며, 그 경우에도 할 일에서 직접 확인한 항목만 변경돼요.

루틴의 작업이 게시물이나 메시지를 보내는 단계로 이어지면, 그 단계까지 진행한 뒤 초안을 보여 줘요. 예를 들면 **X에 게시할 내용:**처럼 표시돼요. 실제 실행 후에는 승인할 수 있도록 할 일로 표시돼요. 테스트 실행에서는 결과만 보여 줘요. 이름에는 내용과 게시 위치가 표시되고, 버튼에는 **게시하기**처럼 실행할 단계가 표시돼요. 아래의 **루틴에서**를 누르면 해당 루틴이 열려요.

할 일은 메시지를 보낼 계정의 영역에서 시작해요. 예를 들어 회사의 X 계정에서 보낼 내용은 업무 영역에서 시작하므로, 다른 영역으로 옮기라는 메시지가 표시되지 않아요.

루틴은 작업 내용에 따라 켜져 있는 [스킬](skills.md)을 사용할 수 있어요. 해당하는 스킬만 전체 내용을 읽어요. 결과의 **사용한 항목:** 아래에 스킬이 표시돼요. 스킬이 루틴을 통해 메시지를 보내거나 내용을 변경하는 일은 없어요.

제안 항목 아래의 **루틴**에서 내 루틴을 확인할 수 있어요. 결과가 길면 짧은 미리 보기로 접혀요. **더 보기**를 누르거나 결과를 탭하면 전체 내용을 볼 수 있어요.

각 실행은 직전 결과를 알고 있으므로, 그 뒤로 바뀐 점을 알려 줄 수 있어요.

성공적으로 실행된 뒤에는 The Machine이 매번 같은 방식으로 읽는 작업을 위한 절차를 직접 만들 수 있어요. 예를 들어 확인할 이메일이나 GitHub 변경 사항을 정할 수 있어요. 다음 실행부터는 일반 코드로 먼저 읽고, AI가 중요한 내용을 골라 작성하므로 토큰을 덜 사용해요. 절차는 읽기만 해요. 작동하지 않으면 해당 실행에서 직접 읽고 문제를 해결해요. ⋯ 메뉴의 **고급: 스크립트 단계** 아래에서 확인할 수 있어요.

## 놓친 날짜

The Machine이 꺼져 있거나 바빴을 때 놓친 실행은 쌓아 두지 않아요. 가장 최근 실행만 한 번 실행돼요. 재시작한 뒤에도 날짜별로 한 번씩만 실행돼요.

루틴은 한 번에 하나씩 실행되며, AI 요금제 사용량이 부족하면 백그라운드 작업과 마찬가지로 대기해요. **지금 실행**을 누르면 바로 실행돼요. 결과가 준비되면 카드에 표시돼요.

## 변경 또는 중지

루틴의 ⋯ 메뉴에서 변경할 수 있어요. **수정**을 누르면 이름과 작업 내용을 바꿀 수 있어요. 실행 시점과 지금까지의 결과는 그대로 유지돼요. **시점 변경**을 누르면 "평일마다 8시"처럼 원하는 문구로 주기를 설정할 수 있어요. 두 메뉴에는 **저장**과 **취소**가 있어요. 컴퓨터에서는 Esc 키를 누르거나 바깥을 클릭해도 취소돼요.

**수정**에서 **사용해 보기**를 누르면 새 문구로 한 번 실행하고 결과를 보여 줘요. **저장**을 누르기 전까지 루틴은 기존 설정 그대로예요.

**일시 정지**를 누르면 **재개**할 때까지 실행이 중지돼요. 일시 정지된 루틴은 맨 아래의 **일시 정지됨** 아래에 표시되며, 일시 정지 중에 놓친 실행은 나중에 실행되지 않아요. **중지**를 누르면 루틴이 완전히 종료돼요.

루틴의 할 일에서 **수정 요청**을 사용하거나 채팅에 메모를 남겼을 때, "이모지는 절대 사용하지 마세요"처럼 모든 실행에 적용하려는 내용이면 할 일과 답장 아래 채팅에 **루틴도 변경**이 표시돼요. 루틴 문구에서 바뀌는 내용을 보여 주며, **변경**을 눌러야 루틴이 바뀌어요. **그대로 유지**를 누르면 바뀌지 않아요. 해당 초안만 수정하는 내용이면 이 옵션은 표시되지 않아요.

## 고급: 스크립트 단계

스크립트는 필요하지 않아요. 루틴이 할 일을 평소 말로 적으면 나머지는 The Machine이 처리해요.

고급 사용자는 The Machine에서 직접 명령어를 실행하는 루틴도 만들 수 있어요. ⋯ 메뉴에서 **고급: 스크립트 단계**를 선택하세요. 루틴에 스크립트 단계가 있어야 **수정**에서 해당 단계를 볼 수 있어요. **데이터 가져오기**는 먼저 명령어를 실행해요. 지정한 폴더에서 실행하며, 폴더를 비워 두면 홈 폴더에서 최대 지정 시간(초) 동안 실행돼요. 명령어가 출력한 내용은 실행 결과를 만드는 데 사용돼요. 문구를 입력하지 않으면 출력한 내용이 결과가 돼요.

**확인**은 실행 후 결과를 입력으로 받아요. 오류와 함께 종료되면 실행 결과에 **작동하지 않았어요**와 확인 단계의 메시지가 표시돼요. 데이터 가져오기 명령어가 실패해도 같은 방식으로 표시돼요.

명령어는 한 줄이며 셸 없이 실행돼요. 파이프나 변수는 사용할 수 없어요. 스크립트 단계는 직접 설정하며 대시보드에서만 설정할 수 있어요. 테스트 실행과 **사용해 보기**에서도 데이터 가져오기를 실행하며, 실행 사실을 알려 줘요. 그래도 아무것도 전송하거나 저장하지 않아요. 루틴은 전송하지 않으므로 스크립트 단계에서는 읽기만 해야 해요.

## OpenClaw 작업에서 가져오기

이전에 OpenClaw에서 예약 작업을 만들었다면 The Machine이 작업을 읽고, 루틴으로 사용할 만한 항목을 **추천됨** 아래에 표시해요. OpenClaw 작업은 변경하지 않아요. 각 작업은 이미 한 번 실행됐으므로 실제 결과를 확인할 수 있어요.

작업에 적용한 수정 사항은 유지하고, 전송하거나 게시한 내용은 제외해요. 스크립트를 실행한 작업이나 스크립트 작업이 수집한 내용을 읽은 작업은 해당 스크립트를 데이터 가져오기로 가져와요. **추가**를 누르면 루틴이 만들어지고, **아니요, 괜찮아요**를 누르면 해당 작업은 다시 묻지 않아요. 무언가를 하라고 알려 주는 작업은 대신 할 일에서 반복 할 일 제안으로 표시돼요.

제안을 추가하기 전에는 ⋯ 메뉴의 **수정**과 **시점 변경**을 사용해 다른 루틴처럼 내용을 바꿀 수 있어요. **다시 실행**을 누르면 현재 문구로 즉시 실행해 새 결과를 확인할 수 있어요. 예를 들어 조용했던 주말이 지난 뒤 실행할 수 있어요. 읽기만 하며, 누를 때마다 한 번 실행되고 새 결과가 이전 결과를 대체해요.

한 번에 최대 세 개의 제안이 표시돼요. 루틴이 일주일 동안 성공적으로 실행되면 **기존 OpenClaw 작업을 끌까요?**라고 물어요. **끄기**를 눌러야 작업이 꺼지며, OpenClaw에서 다시 켤 수 있어요.

## 평소 하는 작업에서 제안

The Machine은 OpenClaw가 없어도 정기적으로 하는 작업을 알아채고 **추천됨** 아래에 루틴으로 제안해요. 다음과 같은 작업을 찾아요.

- 같은 요청을 연속해서 세 번 이상 하는 경우. 예를 들어 매주 월요일에 "열려 있는 지원 티켓 요약하기"라고 요청하는 경우
- 매주 팀에 보고서를 보내는 것처럼 주기적으로 이메일을 보내는 경우
- 매주 계속 도착하는 뉴스레터와 업데이트 이메일
- 다른 사람들이 매주 글을 올리는 Slack 채널 중 활동량이 많은 채널
- 학교나 동아리 이메일을 파트너에게 보내는 것처럼, 같은 사람에게 이메일을 하나씩 계속 전달하는 경우. 매주 요약을 보내면 전달 작업을 줄일 수 있어요.
- 매달 같은 사람에게 승인을 해 주는 것처럼, 같은 요청에 주기적으로 답하는 경우

각 제안에는 "연속 4회 요청" 또는 "3주 동안 Sam에게 이메일 6개 전달"처럼 확인한 내용을 표시해요. 제안은 한 번 실행되므로 실제 결과를 볼 수 있어요. 팀 요약, 주간 통화 전 브리핑, 지원이나 개발 요약, 주요 수치 확인, 받은 뉴스레터 요약 등을 생각해 보세요.

나에게 해당하고 분명히 유용한 내용만 제안해요. 뉴스 요약은 내가 받은 뉴스레터만 대상으로 하며, 일반적인 뉴스 요약은 제안하지 않아요. 해당하는 내용이 없으면 제안도 없어요.

하루에 최대 한 번 확인하고, 일주일에 새 제안을 최대 하나씩 표시해요. 알림은 보내지 않아요. **아니요, 괜찮아요**를 누르면 해당 제안은 다시 표시되지 않아요. 전달한 이메일과 답장은 발신한 계정에 남으므로 업무용과 개인용이 섞이지 않아요. 모든 내용은 The Machine에만 저장돼요. 주기적으로 완료하는 할 일은 대신 반복 할 일 제안으로 표시돼요.

## 루틴과 반복 할 일

반복 할 일(recurring.md)은 무언가를 하도록 알려 줘요. 루틴은 The Machine이 알아서 작업하고 결과를 보여 줘요. "매달 1일에 월세 내기"에는 반복 할 일을, "매주 금요일에 한동안 조용했던 거래 알려 주기"에는 루틴을 사용하세요.
