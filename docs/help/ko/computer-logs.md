## 읽는 정보

Linux에서 systemd를 사용하는 경우, 내 Machine은 내 사용자 세션의 로그만 읽어요. 직접 사용하는 서비스와 프로그램의 충돌 보고서예요. Omarchy에서는 Hyprland와 상태 표시줄도 확인해요. 시스템 전체 로그는 읽지 않고, 추가 권한을 요청하지도 않아요.

어떤 서비스가 중지됐는지, 어떻게 종료됐는지, 어떤 프로그램이 충돌했는지 확인해요. 로그 줄의 내용은 읽지 않으므로 로그 텍스트는 저장되지 않고 컴퓨터 밖으로 전송되지도 않아요.

## 문제로 판단하는 경우

계속 다시 시작되는 서비스, 하루에 여러 번 실패하거나 중지된 상태로 계속 있는 서비스, 메모리가 부족해진 서비스, 충돌한 프로그램이 문제에 해당해요. Omarchy에서는 Hyprland나 상태 표시줄의 충돌, Hyprland 설정 오류도 해당해요.

한 번 다시 시작되거나 한 번 실행에 실패하는 것은 흔한 일이므로 알리지 않아요. 몇 번 실패한 뒤 다시 정상적으로 실행된 서비스도 마찬가지예요. 실행하도록 요청한 곳이 없는 실패한 서비스도 알리지 않아요. 즉, 활성화되어 있지 않고 다른 서비스나 타이머에서도 시작하지 않는 서비스예요.

테스트나 에이전트가 제어하는 브라우저(헤드리스, Playwright, Puppeteer, CI)는 알리지 않아요. 서비스가 중지되거나 다시 시작되는 중에 종료되는 프로그램도 마찬가지예요. 개발 중 실행한 프로그램도 알리지 않아요. 코딩 에이전트가 실행하는 프로그램, 테스트, 임시 폴더나 캐시 폴더에서 실행하는 프로그램이 여기에 해당해요. 프로그램이 반복해서 충돌하면 몇 번, 언제 충돌했는지 알려주는 할 일을 하나 만들어요.

스크립트는 python3나 node가 아니라 backup.py처럼 스크립트 자체의 이름으로 표시해요.

## 표시되는 내용

무슨 일이 있었는지, 왜 중요한지, 어떻게 조치할 수 있는지 쉬운 말로 알려주는 할 일이 표시돼요. 원인을 보여주는 명령어는 **더 보기** 아래에 있어요. 할 일의 채팅에서 물어보면 The Machine이 살펴봐요. **실행**을 누를 때처럼, 변경 사항은 모두 확인을 받은 뒤 적용돼요.

안전한 해결 방법이 있으면 할 일에 **실행**이 표시돼요. 내 서비스가 계속 중지된 상태라면 다시 시작하고, Omarchy에서는 상태 표시줄을 다시 띄워요. **실행**을 누르면 해당 명령어만 실행되고, 결과는 할 일의 채팅에 표시돼요. The Machine 자체의 서비스나 OpenClaw Gateway에는 손대지 않아요.

같은 문제로는 2주에 할 일이 최대 하나만 만들어지고, 해당 할 일이 아직 열려 있으면 새로 만들지 않아요. 하루에 새로 만들어지는 할 일은 최대 두 개예요. 중지된 서비스에 관한 할 일은 서비스가 다시 실행되거나 문제가 해결되면 자동으로 닫혀요.

## 터미널에서

`assistant doctor`을 실행하면 지난 하루 동안 발생한 동일한 문제를 볼 수 있어요.

## 다른 컴퓨터

macOS, Windows, systemd가 없는 컴퓨터에서는 아무것도 읽지 않고, `assistant doctor`에서 그 사실을 알려줘요.

호스팅된 Machine에서는 서버를 계속 실행하는 책임이 우리에게 있어요. 서버 문제는 할 일로 표시되지 않고 The Machine 팀에 전달돼요.

## 끄기

config.json에서 `"computer_logs": false`을 설정하고 서비스를 다시 시작하세요.
